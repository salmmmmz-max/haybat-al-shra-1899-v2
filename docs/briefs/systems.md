# Module part — GAMEPLAY SYSTEMS (interact · الفراسة · الثبات · water · objectives · stars · tracks)

**Owned files**: `game/src/systems/interact.js` · `firasa.js` · `steady.js` · `survival.js` · `objectives.js` · `stars.js` · `tracks.js` (all in `game/src/systems/`; NOT `director.js`, which is kernel) · `game/harness/systems.js` · `game/tests/unit/systems.test.js`.
Contract: ARCHITECTURE §6; DESIGN §3–§4 (every number there is frozen) and §8; glue items 1–8. The current files are simple baselines — implement the full contract. Read `systems/director.js` to see how beats use you (`d.objective`, teardown → `onBeatEnd()`).

These systems ARE the game's verbs. They must be exact (frozen numbers), fair on a touch screen, abort-safe (every promise through `G.scope`; a beat can be cancelled at any tick) and fully testable headlessly (`fastText`).

## interact.js
The only reader of the `interact` action. Each tick resolves ONE verb by priority: (1) `steady` if a steady request is open, (2) `swing` if `player.item === 'torch'` and `G.actors.wolves.threat` (a press → `player.swing()`), (3) `use` — the nearest enabled entry within its radius (2.4 m on foot, 3.5 m mounted; entries need `mountedOk` to be usable from the saddle; prefer what the camera looks toward when two are close). `add({ id, at, radius, label, enabled, onUse, mountedOk, once, hold })` → `{ remove(), setEnabled(b), setLabel(key) }`; `hold` seconds fills `verb.progress` while held (releasing drains it), `onUse` fires once at 100 %; a tap entry fires on press. `verb` per glue 3; emits `interact:verb` when it changes and `interact:use { id }`. `suspend(tag)` / `resume(tag)`. Nothing is usable outside mode `play`. Entries added through a beat die with the beat (`G.scope.own` the handle when called inside a beat; expose `onBeatEnd()`/`onLevelUnload()` cleanup too).

## firasa.js
Hold (or toggle, `settings.firasaToggle`) the eye: `active`, `amount` (eases in 0.25 s; includes the **6 s afterglow** after release — the last 2 s fade out; during the afterglow clues stay lit at full walking speed). Side effects per glue 8. Range 45 m (`setRange(14)` in the storm). `addClue({ id, at, type, radius, onSeen })` → `{ remove(), seen }`: `onSeen` once when the view centre stays within 12° of the clue for 0.4 s while `amount > 0.5` and the clue is within range (`type: 'star'` ignores range); an unseen clue entering range off-screen → one `firasa:ping { bearing }`. `firasa:on` / `firasa:off` / `firasa:seen { id, type }`. `setAllowed(false)` disables the verb (button hidden by the UI through `ui.hud.show`, not by you). Not active in `dialogue`/`cine`.

## steady.js
- `hold({ target, seconds, labelKey, tolerance = 35°, window = Infinity, resolve = 'full' | 'windowEnd', breakOn = 'never' | 'empty' | 'flinch', stages })` → `Promise<boolean>`: opens a request (glue 4), soft-locks the camera on `target`; the ring fills while `interact` is held and the view is within `tolerance`; outside a test window releasing only drains it at 2× the fill rate (`breakOn: 'empty'` → resolves `false` when it has drained to 0 after having been above 15 %); `stages` `[fn33, fn66]` fire once each; resolves `true` at 100 % (`resolve: 'full'`) or at the end of `window` seconds if the ring is ≥ 99 % full then (`'windowEnd'`). `steady:start { seconds, labelKey, target }`, `steady:progress { p }`, `steady:stage { n }`, `steady:end { ok }`.
- `tense(on)`: a TEST WINDOW (a feint, a shot, the dagger). With `breakOn: 'flinch'`, inside a window a flinch fails the hold at once: button released for > 0.25 s, or stick magnitude > 0.5, or the view > 35° off the target. `steady.tension`.
- `brace({ warn, impactAt })` → `Promise<boolean>`: a gust. The button must be down at `impactAt` seconds from now and stay down 1.0 s after; no facing test; while braced the hero is rooted (`player.limit('brace', { speedMul: 0.2 })`). You only judge; the chapter performs the knockdown.
- `walk({ to, radius = 3, speed = 1.5 })` → `{ done: Promise<boolean>, shot() }` (chapter 5): while active the hero's speed is locked to `speed` for any stick ≥ 0.2 (`player.limit('walk', { speed, run: false })`); a flinch (→ `done` resolves `false`) = standing still > 0.5 s, or heading > 35° away from `to` for > 0.4 s, or the stick dropping below 0.2 within 0.8 s after `shot()`; reaching `radius` of `to` → `true`.
- Assist bookkeeping is the chapter's job (it passes shorter `seconds`); you provide `steady.fails(tag)` / `steady.fail(tag)` counters that persist across beat retries and reset on chapter start (`beat:start` with a new chapter).
- `fastText`: holds complete in ≤ 0.1 s without aiming or pressing; `brace` → `true`; `walk` teleports nothing but resolves `true` as soon as the hero is within radius (the bot walks him there).

## survival.js
`thirst` 0–100 (100 = full comfort, 0 = collapse), `sips`. `set({ thirst?, sips?, drain? })`. With `drain` on and mode `play`, per-second drain by state (DESIGN §4): riding 0.16 (0.24 on soft sand), walking 0.15, running 0.35, standing 0.05, plus `rate(tag, perSecond | null)` extras set by chapters (e.g. storm on foot replaces walking with 0.08 → the chapter calls `rate('storm', -0.07)`; night/shade → `set({ drain: false })`). No drain in `dialogue`/`cine` or while paused. Thresholds emit `survival:level { step }` once each going down: 40 (dry breath), 30 (haze), 15 (no running — glue 8 — and heartbeat); 0 → `survival:collapse` (once; the director restarts the beat). Drinking per glue 7: +35 (cap 100), `sips − 1`, emits `survival:drink`, `drinkProgress`. `survival:changed` at most 4×/s. Expose pure helpers for the unit tests.

## objectives.js
`set(key, { vars, at, bearingFn, mark = 'hint' | 'always' | 'never', hints: [k1, k2], hintAfter: [s1, s2], progress })`; `current` / `hint` / `marks` per glue 2. Hint clocks run only in mode `play` and only while there is **no progress**: progress = `progress()` grew, or the distance to `at` dropped by ≥ 8 m since the last mark, or a clue/interaction completed (`firasa:seen`, `interact:use`) — any of these restarts the clock. Defaults for `hintAfter`: `[25, 50]` in chapters 1–2, `[45, 90]` in chapters 3–5. At `hintAfter[i]` → `hint:show { key: hints[i], text, level: i + 1 }`; after the last hint a `goal` mark appears on the strip if `mark === 'hint'` (`'always'` shows it from the start). `poke()` re-emits the current hint (or the objective). `done()` → `objective:done`. `mark(id, { at | bearingFn, icon, scope = 'beat' | 'level' })` → `{ remove() }` — learned marks for the horizon strip; `bearingFn` returns degrees or null (e.g. `() => sky.sunBearing()`, a star's azimuth from `sky.stars.dir`). Beat-scoped marks die in `onBeatEnd()`.

## stars.js
`find({ star, seconds = 0.8, tolerance = 7°, magnet = 12°, decoys })` → Promise: requires night sky mode: turns on `cam.skyMode(true)` and `cam.magnet(() => dir, magnet)`; while the eye (`firasa`) is held and the view axis is within `tolerance` of `G.world.sky.stars.dir(star)` the dwell fills (`stars.active`, `stars:progress { p }`, `sky.stars.highlight(star, p)`); at 100 % → `stars:found { id }`, resolve. Resting the gaze ≥ 0.6 s on a decoy calls its `onGaze` once (a hint, never a fail). Leaving restores the camera (in `finally`). `fastText` → resolves in ≤ 0.1 s.

## tracks.js
`add({ id, points, kind, fresh = 1, spacing, gaps: [[i0, i1]], hidden = false, reveal })` → `{ reveal(), hide(), progressOf(pos) → 0..1, distanceTo(pos) → m, end, remove() }`: renders through `G.world.decals.trail` (one decal trail per continuous run between `gaps`), registers `track` clues along it for the firasa system (one every ~12 m; fresh trails only), and — when `reveal` metres is given (the storm) — calls `trail.setReveal(player.pos, reveal · (firasa.amount > 0.5 ? 1 : 0.35))` every tick so prints appear by distance, never by a timer. `progressOf` / `distanceTo` are allocation-free polyline projections (unit-test them).

## Harness `systems` and unit tests
Params `sys=interact|firasa|steady|brace|walk|survival|objectives|stars|tracks`: each builds a tiny situation on the baseline world and exposes drivers on `window.__harness.api` so that `--eval` scripts can play it with `__hs.input` and assert outcomes (`--print`). Cover success AND failure paths: a flinch inside a test window, a release outside one, a missed brace, the afterglow timing, hint timing with and without progress, thirst thresholds, decoy gaze. Unit tests (`node --test`) for the pure parts: drain table, threshold crossing, hint clock, polyline projection, flinch rules as a pure state machine.
